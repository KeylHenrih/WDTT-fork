# ADR 0001: Структура Cargo Workspace и технологический стек

## Статус
Принято (Предложено на Этапе 0)

## Контекст
Проект `wdtt-rs` представляет собой многокомпонентную кроссплатформенную экосистему, включающую низкоуровневое сетевое ядро (высокопроизводительный datapath), серверный бинарник, системный демон для ПК, Slint GUI для десктопа и клиентское приложение под Android (Kotlin Compose + UniFFI).

Ключевые требования:
- Максимальная производительность и минимальная задержка на сетевом пути.
- Минимальное потребление памяти (GUI $\le 40$ МБ, демон $\le 20$ МБ).
- Четкое разделение ответственности без взаимных циклических зависимостей.
- Безопасность кода: `#![forbid(unsafe_code)]` во всех модулях, кроме строго изолированных системных вызовов с документированным обоснованием.

## Рассмотренные варианты
1. **Монолитный крейт с feature flags:**
   - *Минусы:* смешение зависимостей, раздувание времени компиляции, случайное попадание тяжелых зависимостей GUI или Android в ядро/сервер.
2. **Многокрейтовый Cargo Workspace:**
   - *Плюсы:* строгая модульность, независимая сборка и тестирование, точечное управление зависимостями, возможность раздельного профилирования и фаззинга каждого слоя.

## Решение
Принята модульная архитектура Cargo Workspace (Rust edition 2024):

```
crates/proto        # Кадры v2, парсер ссылок (wdtt://, qwdtt://, wdtt2://), без сетевого I/O
crates/crypto       # AEAD (ChaCha20-Poly1305 / AES-GCM), HKDF, zeroize, RFC 6479 replay-окно
crates/turn         # Минимальный асинхронный STUN/TURN клиент (UDP/TCP/TLS)
crates/provider     # Trait TurnCredentialProvider, vk (изолированная логика), static, rest
crates/core         # Сессии, адаптивный пул потоков, flow-hash планировщик, статистика
crates/tun          # TUN-абстракция (Linux netlink, Windows wintun, macOS utun, Android fd)
crates/ipc          # Протокол демон <-> GUI (формат postcard, IPC сокеты/named pipes)
crates/server       # Высокопроизводительный серверный бинарник (SO_REUSEPORT, recvmmsg)
crates/daemon       # wdttd (системная служба ПК)
crates/gui-desktop  # Нативный Slint GUI
crates/ffi-android  # UniFFI биндинги + cargo-ndk
android/            # Kotlin + Jetpack Compose приложение
docs/               # Документация и ADR
scripts/            # Скрипты бенчмаркинга, сборки и деплоя
bench/              # Criterion микробенчмарки
```

### Профиль сборки Release:
- `lto = "fat"`
- `codegen-units = 1`
- `panic = "abort"`
- `strip = true`
- Глобальный аллокатор: `mimalloc` (с верификацией выигрыша на Android/musl).

## Последствия
- Полная изоляция чисто протокольного и криптографического кода (`proto`, `crypto`) от сетевого I/O, что делает их идеальными кандидатами для непрерывного фаззинга (`cargo-fuzz`) и property-based тестирования (`proptest`).
- Строгое соблюдение `#![forbid(unsafe_code)]` в 9 крейтах из 10. Единичные `unsafe` допускаются только в `crates/tun` (системные ioctl, перехват fd) и FFI-границах с явным комментарием `// SAFETY: ...`.
