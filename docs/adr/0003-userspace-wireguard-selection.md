# ADR 0003: Выбор реализации WireGuard (Kernel vs Userspace / boringtun)

## Статус
Принято (Предложено на Этапе 0)

## Контекст
Проект требует гибкого взаимодействия с WireGuard:
- На стороне сервера: максимальная производительность для обслуживания множества клиентов.
- На стороне клиентов ПК: работа на Linux, Windows и macOS без внешних бинарников `wg`/`ip` и без требования sudoers.
- На стороне Android: интеграция с виртуальным TUN `VpnService`.

## Рассмотренные варианты
1. **Исключительно системный Kernel WireGuard:**
   - *Плюсы:* нулевой оверхед на криптографию внутри userspace, поддержка аппаратного шифрования в ядре Linux.
   - *Минусы:* требует наличия модуля ядра `wireguard` на сервере (не всегда доступен в некоторых OpenVZ/LXC VPS), не применим напрямую на Android и macOS без системных расширений.
2. **`wireguard-go`:**
   - *Минусы:* Go runtime, сборщик мусора (GC), высокое потребление памяти (40–90 МБ), несовместим с целью создания компактного легковесного Rust-бинаря.
3. **`boringtun` (Cloudflare) в качестве Userspace WireGuard:**
   - *Плюсы:* написан на Rust, лицензия BSD-3-Clause (полная совместимость с GPL-3.0), высокая производительность, оптимизированные реализации криптографических примитивов (ChaCha20-Poly1305, Curve25519), proven in production (Cloudflare WARP).
   - *Минусы:* оверхед на переключение контекста между ядром (TUN) и userspace по сравнению с ядром Linux.

## Решение
1. **На сервере (Linux):**
   - **По умолчанию:** интеграция с **Kernel WireGuard** через пересылку расшифрованных пакетов на локальный UDP-порт (`127.0.0.1:<wg_port>`). Это обеспечивает максимальную скорость (гигабитный wire-speed) и использование оптимизаций ядра.
   - **Опционально (Feature Flag `userspace-wg`):** встроенный userspace WireGuard на базе `boringtun` для хостов без модуля ядра Linux.
2. **На ПК (клиент `wdttd`):**
   - Управление системным TUN-адаптером (netlink на Linux, Wintun на Windows, utun на macOS) с userspace обработкой через `boringtun`.
3. **На Android:**
   - Приём сырых IP-пакетов из `ParcelFileDescriptor` (TUN fd) и их обработка ядром `boringtun` в рамках единого нативного процесса без проксирования через сетевой стек Android.

## Последствия
- Полная автономность: клиенту и серверу не требуются внешние утилиты `wg`, `wireguard-tools` или сторонние демоны.
- На Android устраняется «двойной цикл» сетевых буферов между GoBackend и прокси, что существенно снижает задержку и расход аккумулятора.
