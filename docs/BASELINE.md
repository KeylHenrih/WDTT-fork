# Руководство по снятию Baseline производительности (`docs/BASELINE.md`)

Данная инструкция предназначена для ручного снятия эталонных показателей (baseline) действующего туннеля **PWDTT / WDTT Plus** на внешнем сервере (`<SERVER_TUNNEL_IP>`) с клиентского ПК (Linux/macOS/Windows) и Android-смартфона.

Методика и параметры полностью согласованы со стендовыми тестами WDTT v2 ([docs/BENCHMARKS.md](BENCHMARKS.md)) для обеспечения строгой сопоставимости результатов.

---

## 1. Подготовка стенда и запуск iperf3 на сервере

1. Подключитесь по SSH к серверу:
   ```bash
   ssh user@<SERVER_HOST>
   ```
2. Убедитесь, что туннельный интерфейс активен (`<SERVER_TUNNEL_IP>`).
3. Запустите серверный процесс `iperf3` в режиме ожидания одного теста на порту `5201` (привязка к IP туннеля):
   ```bash
   iperf3 -s -B <SERVER_TUNNEL_IP> -p 5201 -1
   ```
   *(После каждого теста с флагом `-1` iperf3 завершается; перезапускайте команду перед каждым новым замером).*

---

## 2. Замеры с клиентского ПК (Linux / macOS / Windows)

Перед началом убедитесь, что клиентский туннель PWDTT/WDTT Plus запущен и подключён (IP клиента в туннеле: `<CLIENT_TUNNEL_IP>`).

### 2.1 Тест задержки и стабильности (ICMP Ping)
Выполните 100 пакетов с интервалом 20 мс:
```bash
ping -c 100 -i 0.02 <SERVER_TUNNEL_IP>
```
*Зафиксируйте:*
- `packet loss %` (потери пакетов)
- `rtt min / avg / max / mdev`

### 2.2 Одиночный TCP-поток (10 секунд)
На сервере: `iperf3 -s -B <SERVER_TUNNEL_IP> -p 5201 -1`  
На клиенте:
```bash
iperf3 -c <SERVER_TUNNEL_IP> -p 5201 -t 10
```
*Зафиксируйте:*
- Пропускная способность (Receiver Bitrate, Мбит/с)
- Число ретрансмитов (`Retr`)

### 2.3 4 параллельных TCP-потока (10 секунд)
На сервере: `iperf3 -s -B <SERVER_TUNNEL_IP> -p 5201 -1`  
На клиенте:
```bash
iperf3 -c <SERVER_TUNNEL_IP> -p 5201 -t 10 -P 4
```
*Зафиксируйте:*
- Суммарная пропускная способность (`[SUM] Receiver Bitrate`, Мбит/с)
- Суммарное число ретрансмитов (`[SUM] Retr`)

### 2.4 UDP-поток 100 Мбит/с (10 секунд)
На сервере: `iperf3 -s -B <SERVER_TUNNEL_IP> -p 5201 -1`  
На клиенте:
```bash
iperf3 -c <SERVER_TUNNEL_IP> -p 5201 -t 10 -u -b 100M
```
*Зафиксируйте:*
- Фактический битрейт (Мбит/с)
- Джиттер (`Jitter`, мс)
- Потери дейтаграмм (`Lost/Total Datagrams`, %)

### 2.5 Снятие утилизации CPU и памяти RSS клиента (Linux)
Во время прохождения 10-секундного теста TCP в соседнем терминале:
```bash
# Использование CPU и RSS за 10 секунд с интервалом 1 секунда
pidstat -u -r -p $(pgrep -f "pwdtt|wdtt") 1 10
```
Или моментальный снимок:
```bash
ps -C pwdtt -o %cpu,rss,comm
```
*Зафиксируйте:*
- Средний % CPU
- Размер RSS памяти в МБ (`RSS_KB / 1024`)

## 3. Замеры со смартфона (Android)

Подключите смартфон к активному туннелю через мобильное приложение WDTT Plus / WireGuard.

1. Установите `iperf3` (через Termux: `pkg install iperf3` или через графическое приложение "Magic iPerf").
2. В Termux выполните аналогичные команды:
   - **Ping:** `ping -c 100 -i 0.02 <SERVER_TUNNEL_IP>`
   - **TCP 1 поток:** `iperf3 -c <SERVER_TUNNEL_IP> -p 5201 -t 10`
   - **TCP 4 потока:** `iperf3 -c <SERVER_TUNNEL_IP> -p 5201 -t 10 -P 4`
   - **UDP 100M:** `iperf3 -c <SERVER_TUNNEL_IP> -p 5201 -t 10 -u -b 100M`
3. Снятие метрик потребления через ADB (с подключённого ПК):
   ```bash
   # Загрузка CPU клиентом:
   adb shell top -n 1 -b | grep -i wdtt

   # Память приложения:
   adb shell dumpsys meminfo <имя_пакета_клиента> | grep "TOTAL PSS:"
   ```
